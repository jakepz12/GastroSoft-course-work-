# GastroSoft — Архитектура приложения

## 1. Общее описание

GastroSoft — desktop-прототип системы автоматизации ресторана на Python 3.14+ и PySide6 (Qt). Приложение предназначено для управления заказами, кухней, бронированиями, складом и персоналом. Работает с MySQL базой данных, при её отсутствии переключается на демо-режим с пустыми данными.

## 3. Архитектура приложения (по слоям)

### 3.1. Точка входа
**`run_gastrosoft.py`** → вызывает `gastrosoft_app.app.main()` → создаёт `QApplication` и `GastroSoftWindow`.

### 3.2. Главное окно (`shell.py`)
Класс `GastroSoftWindow(QMainWindow)` — каркас приложения:
- **Боковая панель навигации** — кнопки страниц (Dashboard, Смены, Бронирования, Заказы, Кухня, Склад)
- **Хедер** — заголовок текущей страницы, роль пользователя, кнопка «Выйти»
- **QStackedWidget** — контейнер страниц, переключение по навигации
- **Строка состояния** — уведомления внизу экрана

При запуске создаёт `MySQLBackedStore` (обёртка над MySQL), создаёт все страницы и показывает страницу авторизации.

### 3.3. Слой данных (`mysql_store.py` — ~1500 строк)
Класс `MySQLBackedStore(DemoStore)` — центральный посредник между UI и базой данных.

**Основные функции:**
- `authenticate()` — вход пользователя через логин/пароль (SHA-256 хеш)
- `register_user()` — регистрация нового сотрудника
- `reload_from_mysql()` — перезагрузка всех данных из БД
- `send_draft_to_kitchen()` — отправка заказа из черновика в БД
- `advance_order_status()` — смена статуса заказа (Принят → Готовится → Готов → Выдан)
- `complete_order()` — закрытие заказа (для кассира)
- `apply_inventory_operation()` — складская операция

**Методы модуля кухни:**
- `get_active_orders_for_kitchen()` — все активные заказы с позициями
- `get_order_items(order_id)` — позиции заказа с индивидуальными статусами
- `mark_item_ready(item_id)` — отметить конкретное блюдо как готовое
- `assign_cook_to_order(order_id, cook_id)` — назначить повара
- `set_order_priority(order_id, priority)` — приоритет (normal/rush)
- `start_order(order_id)` — начало приготовления (установка started_at)
- `get_kitchen_stats()` — среднее время приготовления, количество в работе
- `get_order_history()` — история заказов

**Fallback:** Если MySQL недоступен, приложение работает через `DemoStore` (пустые коллекции, все методы возвращают ошибки).

### 3.4. RBAC — контроль доступа (`role_access.py`)
Определяет, какие страницы и функции доступны каждой роли:

| Роль | Страницы | Особенности |
|------|----------|-------------|
| Администратор | Все | Полный доступ |
| Директор | Все | Полный доступ |
| Менеджер зала | Бронирования, Заказы | Управление посадкой |
| Официант | Заказы | Создание, контроль и закрытие заказов |
| Шеф-повар | Кухня, Заказы | Управление очередью, распределение |
| Повар | Кухня | Приготовление, отметка готовности |
| Бухгалтер | Склад | Складские операции и отчёты |

### 3.5. Страницы (`pages/`)

**auth_page.py** — Два режима: вход (логин + пароль) и регистрация (ФИО, логин, пароль, роль).

**dashboard_page.py** — KPI-карточки (выручка, заказы, брони, остатки, среднее время кухни), графики продаж по часам и популярных блюд, быстрые действия.

**orders_page.py** — Три колонки:
- Меню (категория + список блюд + кнопка «Добавить»)
- Текущий заказ (стол, оплата, черновик с примечаниями, итого, отправка на кухню)
- Очередь кухни (таблица с фильтрами, статусами, кнопками для кухни/кассы)

**kitchen_page.py** — Карточный вид заказов:
- Сводка (Принято / Готовятся / Готово)
- Фильтр по статусу
- Карточки заказов с таймерами, статусами позиций, кнопками действий
- Назначение повара (для шеф-повара), приоритет (Срочно/Обычный)
- Среднее время приготовления

**reservations_page.py** — Форма брони + карта столов (занят/свободен) + список бронирований.

**staff_page.py** — Список сотрудников + назначение на смены + подбор замены + закрытие смен.

**inventory_page.py** — Остатки ингредиентов + операции (поступление/списание/корректировка) + журнал + текстовый отчёт с экспортом.

### 3.6. Виджеты (`widgets.py`)
- `SectionCard` — карточка-секция с заголовком и подзаголовком
- `MetricCard` — карточка метрики (название + число + пояснение)
- `StatusPill` — цветной индикатор статуса (info/success/warning/danger/muted)
- `apply_button_variant()` — применение стиля кнопки (primary/secondary/warning/danger/ghost)
- `tint_table_item()` — окраска ячейки таблицы

### 3.7. Стили
Каждая страница имеет свой QSS-файл в `styles/<page>/style.css`. Общая палитра:
- Фон: `#F8FAFC`
- Акцент: `#1F686E` (teal)
- Текст: `#1E293B`
- Успех: `#0F766E`
- Предупреждение: `#F59E0B`
- Опасность: `#991B1B`
- Шрифт: Segoe UI
- Скругления: 14–24px

## 4. Схема базы данных

### Основные таблицы:

```
employee_role     — Роли (Администратор, Директор, Шеф-повар, Повар, Официант, Кассир...)
employee          — Сотрудники (ФИО, роль, телефон, email)
app_user          — Учётные записи (логин, хеш пароля, привязка к сотруднику)

restaurant_table  — Столы ресторана (код, вместимость, активность)
guest             — Гости (ФИО, телефон)
reservation       — Бронирования (гость, стол, время, статус, количество гостей)

menu_category     — Категории меню (Закуски, Супы, Горячее, Напитки)
dish              — Блюда (название, цена, время приготовления)
recipe_item       — Рецептура (блюдо → ингредиент → количество)
ingredient        — Ингредиенты (название, цена за ед., критический уровень)
measurement_unit  — Единицы измерения (г, кг, мл, л, шт)

customer_order    — Заказы (стол, статус, создатель, повар, приоритет, время)
order_item        — Позиции заказа (блюдо, количество, цена, статус, примечание, повар)
order_status      — Статусы заказов (Принят, Готовится, Готов, Выдан, Закрыт)
order_item_status — Статусы позиций (В очереди, Готовится, Готово, Подано)

kitchen_log       — Журнал действий на кухне
inventory_operation — Движения по складу
work_shift        — Рабочие смены
shift_assignment  — Назначения сотрудников на смены
```

### Статусы заказа (жизненный цикл):
```
Принят (ACCEPTED) → Готовится (PREPARING) → Готов (READY) → Выдан (SERVED) → Закрыт (CLOSED)
```

### Статусы позиции заказа:
```
В очереди (QUEUED) → Готовится (COOKING) → Готово (READY) → Подано (SERVED)
```

## 6. Пример из жизни: рабочий день в ресторане

### Утро — Начало смены

**8:00** — Шеф-повар **Волков Илья** приходит на смену. Логинится в GastroSoft как `chef`. Его роль — **Шеф-повар**. Он видит главную панель (Dashboard) с показателями: выручка, количество заказов, проблемы со складом, среднее время приготовления. Нажимает «Открыть кухню».

**8:05** — На кухонной панели пока пусто — заказов ещё нет. Илья проверяет склад ингредиентов через Dashboard, видит что помидоров мало (критический остаток).

**8:10** — Официант **Белова Мария** логинится как `waiter`. Её роль — **Официант**. Она видит только страницу заказов. Справа — меню с категориями: Закуски, Супы, Горячее, Напитки. Слева — черновик заказа.

### Обед — Пик заказов

**12:15** — Заходит компания из 4 человек. Мария выбирает стол T-03. Начинает оформлять заказ:
1. Выбирает категорию «Супы» → Том Ям → «Добавить в заказ»
2. В поле примечания пишет «острее» → «Примечание»
3. Категория «Горячее» → Паста Альфредо → «Добавить»
4. Категория «Напитки» → Лимонад базилик-лайм → «Добавить»
5. Выбирает стол T-03, способ оплаты «Карта»
6. Нажимает «Передать на кухню»

**12:15** — На кухонной панели Ильи появляется карточка заказа **GS-1**:
- Стол T-03
- Таймер: 0 мин (зелёный)
- Том Ям × 1 (📝 острее) — статус: В очереди
- Паста Альфредо × 1 — статус: В очереди
- Лимонад базилик-лайм × 1 — статус: В очереди
- Итого: 1 470 ₽

**12:16** — Илья назначает повара **Громова Павла** на заказ через выпадающий список. Нажимает «Назначить повара».

**12:17** — Павел логинится как `cook`. Его роль — **Повар**. Он видит кухонную очередь. Видит заказ GS-1 с пометкой «Повар: Громов Павел». Нажимает «Взять в работу».

**12:17** — Статус заказа меняется на «Готовится». Таймер начинает отсчёт. Цвет таймера: жёлтый (10+ мин).

**12:20** — Павел готовит Том Ям. Гости ждут. Илья видит на своей панели что GS-1 в работе.

**12:25** — Павел заканчивает Том Ям. Нажимает «Готово: Том Ям». Статус позиции меняется на «Готово». Галочка рядом с блюдом.

**12:28** — Павел заканчивает Пасту. Нажимает «Готово: Паста Альфредо».

**12:30** — Лимонад готов. Нажимает «Готово: Лимонад базилик-лайм».

**12:30** — Все позиции готовы. Статус заказа автоматически меняется на «Готов». На Dashboard Марии появляется уведомление.

**12:31** — Мария видит в очереди кухни: GS-1 — Статус: Готов. Выдаёт заказ гостям.

### Срочный заказ

**13:00** — Заходит VIP-гость. Мария оформляет заказ GS-5. Шеф-повар Илья видит его на кухне и нажимает «Срочно». Карточка заказа выделяется красной рамкой, появляется плашка «СРОЧНО». Все повара видят приоритет и берут заказ первым.

### Закрытие заказа

**13:30** — Гости уходят. Мария видит в очереди кухни: GS-1 — Статус: Выдан, Сумма: 1 470 ₽. Нажимает «Закрыть заказ». Заказ закрыт, оплата принята.

### Склад

**14:00** — Бухгалтер **Руднева Светлана** логинится как `accountant`. Видит страницу склада: остатки ингредиентов, критические уровни. Помидоров мало. Она создаёт операцию «Поступление: Томаты, 5 кг» и нажимает «Провести операцию». Остаток обновляется.

## 8. Технические особенности

- **Нет тестов, линтера, CI** — проверка вручную запуском приложения
- **Styles — QSS (Qt Style Sheets)**, не CSS (похожий синтаксис, но не идентичный)
- **Весь текст на русском языке** — интерфейс, роли, данные
- **MySQL порт по умолчанию: 3307** (не 3306)
- **Хеш пароля** — SHA-256, пароль «1234»: `03ac674216f3e15c761ee1a5e255f067953623c8b388b4459e13f978d7c846f4`
- **Fallback** — при недоступности MySQL приложение работает с пустыми данными
