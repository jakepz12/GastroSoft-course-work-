# Функции кухонного модуля GastroSoft

В документе описаны 6 функций кухонного сценария. Блок-схемы построены по ГОСТ 19.701-90: овал — начало/конец, прямоугольник — процесс, ромб — условие.

## Функция 1. Оформление заказа официантом

**Цель:** Создать заказ и передать его на кухню.

**Входные данные:** Список блюд, стол, способ оплаты, примечания.

**Блок-схема:**

```
Начало
  │
  ▼
Официант выбирает блюдо из меню
  │
  ▼
Добавление в черновик заказа
  │
  ▼
Ввод примечания (без лука, острее...)
  │
  ▼
Выбор стола и способа оплаты
  │
  ▼
Нажатие «Передать на кухню»
  │
  ▼
Сохранение в MySQL
  │
  ├── Данные корректны? ──Нет──→ Сообщение об ошибке
  │       │
  │      Да
  │       ▼
  │  Заказ создан со статусом «Принят»
  │  Позиции: статус «В очереди»
  │       │
  │       ▼
  │  Оповещение кухни
  │       │
  └───────┘
         │
         ▼
       Конец
```

## Функция 2. Назначение повара шеф-поваром

**Цель:** Распределить заказ между поварами.

**Входные данные:** Заказ, список поваров.

**Блок-схема:**

```
Начало
  │
  ▼
Шеф-повар видит новый заказ
  │
  ▼
Выбирает повара из выпадающего списка
  │
  ▼
Нажимает «Назначить повара»
  │
  ▼
Запись assigned_cook_id в customer_order
  │
  ▼
Запись assigned_cook_id в order_item
  │
  ▼
Логирование в kitchen_log
  │
  ▼
Повар видит заказ в своей очереди
  │
  ▼
Конец
```

## Функция 3. Приготовление поваром

**Цель:** Принять заказ в работу и отметить готовность.

**Входные данные:** Заказ из очереди.

**Блок-схема:**

```
Начало
  │
  ▼
Повар выбирает заказ
  │
  ▼
Нажимает «Взять в работу»
  │
  ▼
Статус заказа: Готовится
started_at = NOW()
  │
  ▼
Приготовление блюда
  │
  ▼
Повар нажимает «Готово: Блюдо»
  │
  ▼
Статус позиции: Готово
ready_at = NOW()
  │
  ▼
Все позиции готовы?
  │
  ├── Нет → Ожидание
  │
  └── Да
        │
        ▼
  Статус заказа: Готов
        │
        ▼
  Оповещение официанта
        │
        ▼
      Конец
```

## Функция 4. Установка приоритета

**Цель:** Пометить заказ как срочный.

**Входные данные:** Заказ, приоритет (normal/rush).

**Блок-схема:**

```
Начало
  │
  ▼
Шеф-повар видит VIP-гостя
  │
  ▼
Нажимает «Срочно» на карточке заказа
  │
  ▼
Обновление priority = 'rush' в MySQL
  │
  ▼
Карточка заказа выделяется красной рамкой
Появляется плашка «СРОЧНО»
  │
  ▼
Заказ перемещается в начало очереди
  │
  ▼
Все повара видят приоритет
  │
  ▼
Конец
```

## Функция 5. Закрытие заказа официантом

**Цель:** Принять оплату и закрыть заказ.

**Входные данные:** Готовый заказ.

**Блок-схема:**

```
Начало
  │
  ▼
Официант видит статус «Готов» / «Выдан»
  │
  ▼
Выдаёт заказ гостю
  │
  ▼
Выбирает заказ в очереди
  │
  ▼
Нажимает «Закрыть заказ»
  │
  ▼
Статус заказа: Закрыт
closed_at = NOW()
  │
  ▼
Все позиции: статус «Подано»
  │
  ▼
Заказ исчезает из активной очереди
  │
  ▼
Конец
```

## Функция 6. Просмотр отчётов

**Цель:** Анализ работы кухни.

**Входные данные:** Данные из MySQL.

**Блок-схема:**

```
Начало
  │
  ▼
Шеф-повар открывает страницу «Отчёты»
  │
  ▼
Загрузка статистики:
  - Среднее время приготовления
  - Количество выполненных заказов
  - Количество срочных заказов
  │
  ▼
Загрузка истории заказов
  │
  ▼
Просмотр карточек KPI
  │
  ▼
Просмотр таблицы истории
  │
  ▼
Выбор заказа → просмотр состава
  │
  ▼
Генерация текстового отчёта
  │
  ▼
Экспорт в файл (опционально)
  │
  ▼
Конец
```
