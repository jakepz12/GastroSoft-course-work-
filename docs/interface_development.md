# Разработка интерфейса кухонного модуля GastroSoft

## Выбранный стек интерфейса

Для реализации desktop-приложения на Python в проекте используется **PySide6**. Этот фреймворк подходит для кухонного модуля, потому что предоставляет готовые компоненты для настольного интерфейса: таблицы, кнопки действий, карточки, выпадающие списки, статусные метки и панель навигации.

В рамках текущего этапа разработки рассматривается только кухонный модуль GastroSoft. Остальные модули системы не являются предметом изменения интерфейса. Основной акцент сделан на работе двух ролей:

1. **Повар**.
2. **Шеф-повар**.

Общий визуальный стиль приложения сохраняется: используются существующие цвета, шрифты, карточки, таблицы и кнопки. Изменяется не оформление, а логика отображения страниц для кухонных ролей.

## 1. Цели разработки интерфейса

Цель разработки интерфейса кухонного модуля состоит в том, чтобы повар и шеф-повар после авторизации получали быстрый доступ к очереди заказов и могли управлять статусами приготовления без перехода по лишним страницам.

К основным целям относятся:

1. Разделить интерфейс после входа в систему по ролям пользователя.
2. Для ролей `Повар` и `Шеф-повар` открывать кухонную очередь сразу после авторизации.
3. Скрыть для кухонных ролей страницы, которые не нужны в процессе приготовления: главную панель, бронирования, склад, смены и оформление заказа.
4. Оставить в рабочей области кухни только список активных заказов, фильтр статусов и быстрые кнопки обработки.
5. Сделать заказы более читаемыми за счет отдельного отображения номера, стола, времени, состава заказа и текущего статуса.
6. Сохранить существующий дизайн приложения без изменения цветовой схемы и общего визуального стиля.

## Структура раздела

Раздел разработки интерфейса включает:

1. Описание пользователей кухонного модуля.
2. Правила визуального оформления без изменения действующего дизайна.
3. Состав интерфейса кухонной очереди.
4. Сценарий работы повара и шеф-повара.
5. Интеграцию кухонного интерфейса с данными заказов.

## 2. Пользователи кухонного модуля

В кухонном модуле выделяются две пользовательские роли.

### Повар

Повар работает с текущими заказами, которые поступили на кухню. Для него важны скорость реакции, минимум отвлекающих элементов и понятная последовательность действий.

Основные задачи повара:

1. Просмотреть поступившие заказы.
2. Выбрать заказ из очереди.
3. Взять заказ в работу.
4. Отметить заказ как готовый.
5. Видеть только активные кухонные статусы: `Принят`, `Готовится`, `Готов`.

### Шеф-повар

Шеф-повар контролирует состояние всей кухни и отслеживает загруженность по заказам. Его интерфейс совпадает с интерфейсом повара по структуре, но используется для контроля очереди и принятия оперативных решений.

Основные задачи шеф-повара:

1. Видеть общую очередь активных заказов.
2. Контролировать количество заказов в статусах `Принят`, `Готовится`, `Готов`.
3. Быстро фильтровать очередь по статусу.
4. Переводить заказ на следующий кухонный этап.
5. Обновлять очередь заказов из базы данных.

## 3. Шрифты и цветовая схема

Визуальное оформление кухонного модуля не изменяется и строится на уже принятой системе интерфейса GastroSoft:

1. Основной шрифт: **Segoe UI**.
2. Светлый фон рабочей области: `#F8FAFC`.
3. Белый фон карточек и таблиц: `#FFFFFF`.
4. Основной цвет текста: `#1E293B`.
5. Вторичный цвет текста: `#64748B`.
6. Акцентный цвет основных действий: `#1F686E`.
7. Цвет предупреждающих действий и статуса принятого заказа: `#F59E0B`.
8. Цвет успешного состояния готовности: оттенки зеленого/бирюзового, уже применяемые в статусных метках.

Сохранение существующей визуальной схемы важно, потому что задача текущего этапа заключается не в редизайне, а в адаптации интерфейсной логики под кухонный модуль.

## 4. Состав интерфейса кухонного модуля

Кухонный модуль состоит из минимального набора элементов.

### 4.1. Авторизация с учетом роли

После успешного входа система определяет роль пользователя. Если роль равна `Повар` или `Шеф-повар`, приложение открывает не главную панель, а страницу кухонной очереди.

Для кухонных ролей в боковой навигации остается только пункт **Кухонная очередь**. Это уменьшает количество лишних переходов и делает рабочий сценарий прямым.

### 4.2. Очередь кухни

Очередь кухни является основным экраном модуля. В таблице отображаются:

1. Номер заказа.
2. Номер стола.
3. Время создания заказа.
4. Состав заказа.
5. Текущий статус.

Такое представление позволяет быстро понять, какой заказ нужно готовить, какие блюда входят в состав и на каком этапе находится выполнение.

### 4.3. Фильтр статусов

Фильтр позволяет показать:

1. Все активные заказы.
2. Только заказы в статусе `Принят`.
3. Только заказы в статусе `Готовится`.
4. Только заказы в статусе `Готов`.

Фильтрация нужна для работы в загруженную смену, когда повару или шеф-повару требуется быстро отделить новые заказы от уже готовящихся.

### 4.4. Сводные счетчики

Над таблицей отображаются счетчики:

1. `Принято` - количество заказов, которые нужно взять в работу.
2. `В работе` - количество заказов, которые уже готовятся.
3. `Готово` - количество заказов, ожидающих выдачи.

Счетчики помогают шеф-повару оценить текущую нагрузку кухни без просмотра каждого заказа по отдельности.

### 4.5. Быстрая кнопка изменения статуса

Для выбранного заказа кнопка меняет текст в зависимости от текущего состояния:

1. Для статуса `Принят` отображается действие **Взять в работу**.
2. Для статуса `Готовится` отображается действие **Отметить готовым**.
3. Для статуса `Готов` действие блокируется, потому что заказ уже выполнен кухней.

Кухонный модуль не закрывает заказ полностью. Закрытие заказа относится к обслуживанию и оплате, поэтому для ролей кухни эта кнопка скрывается.

## 5. Сценарий работы

Сценарий работы повара и шеф-повара выглядит следующим образом:

1. Пользователь вводит логин и пароль.
2. Система проверяет учетную запись и определяет роль.
3. Если роль относится к кухне, приложение открывает страницу **Кухонная очередь**.
4. Пользователь просматривает список активных заказов.
5. При необходимости пользователь применяет фильтр по статусу.
6. Пользователь выбирает заказ.
7. Система показывает доступное действие для выбранного статуса.
8. Пользователь переводит заказ из `Принят` в `Готовится` или из `Готовится` в `Готов`.
9. Интерфейс обновляет таблицу и счетчики статусов.

## 6. Интеграция с данными

Кухонный интерфейс получает данные из общей очереди заказов `kitchen_queue`. При подключенной MySQL-базе очередь формируется на основе таблиц `customer_order`, `order_status`, `order_item`, `dish`, `restaurant_table` и представления `v_order_total`.

При изменении статуса заказа приложение:

1. Определяет выбранный заказ.
2. Проверяет текущий статус.
3. Выбирает следующий допустимый кухонный статус.
4. Обновляет статус заказа в таблице `customer_order`.
5. Обновляет статусы позиций заказа в таблице `order_item`.
6. Повторно загружает данные из MySQL.
7. Обновляет таблицу очереди и счетчики на экране.

Таким образом, интерфейс кухни связан с базой данных и отражает актуальное состояние заказов без добавления лишних экранов для повара и шеф-повара.
